# VLESS / Hysteria 2 Pipeline

Проект проверяет VLESS/Hysteria 2-ключи через Xray и публикует готовые подписки в отдельный Git-репозиторий.

Требования: Python 3.10+, `curl`, исполняемый `xrayFile/xray` и настроенный вложенный репозиторий `git/`.

## Запуск

```bash
python3 main.py
```

Меню режимов отсутствует. Пайплайн:

- работает по всем ежедневным точкам `START_TIME` из `pipeline_config.py`;
- после завершения остается запущенным и ожидает следующую точку;
- запускается один раз сразу, если `START_TIME = None` или `[]`;
- начинает с `START_STEP`;
- работает только с VLESS/Hysteria 2;
- не отправляет сообщения в Telegram;
- завершает работу через `git commit + push`.

Пример нескольких ежедневных запусков:

```python
START_TIME = ["08:00", "14:00", "21:30"]
```

Также поддерживается строка `"08:00, 14:00, 21:30"`. Времена сортируются,
дубликаты удаляются. Если один запуск завершился ошибкой, процесс не
закрывается и ожидает следующую точку расписания.

## Hysteria 2

Для `whiteList` оцениваются VLESS и Hysteria 2-ключи.

Поддерживаются:

- схемы `hysteria2://` и `hy2://`;
- password и `username:password`;
- SNI, ALPN и `pinSHA256`;
- Salamander и Gecko;
- одиночный порт, диапазоны и списки port hopping;
- порт 443 по умолчанию.

Xray 26.3.27 больше не принимает `allowInsecure`. Поэтому параметр `insecure=1` не переносится в конфигурацию Xray: сервер должен иметь валидный сертификат либо ссылка должна содержать `pinSHA256`.

## Шаги

1. Извлечь и дедуплицировать VLESS/Hysteria 2-ключи из
   `whiteList_top15.txt`: ключи с RU-маркером попадают в RU-пул, остальные —
   в основной пул.
2. Скачать текущие `main`, `WhiteKeys` и `WhiteKeys2`, добавить их ключи к
   кандидатам и найти живые ключи через Xray.
3. Выполнить повторные прогоны и выбрать до 300 лучших ключей на файл.
4. Переписать descriptions: канал, номер и флаг.
5. Подготовить `main`, `WhiteKeys` и `WhiteKeys2`.
6. Собрать `WLTest` из всех URL в `whiteList.txt`: оставить и
   сразу записать все ключи с IP из `normalized_networks.txt`, без ping.
7. Выполнить commit и push вложенного репозитория `git/`.

## Основные файлы

- `main.py` — оркестратор.
- `pipeline_config.py` — расписание, лимиты и параллелизм.
- `src/pipeline_shared_tools.py` — извлечение и дедупликация ключей.
- `src/merge_published_subscriptions.py` — возврат опубликованных ключей в
  очередную проверку.
- `src/ping_keys_with_xray.py` — первичная проверка.
- `src/rerank_ping_ok_keys.py` — повторная проверка и ранжирование.
- `src/write_git_publish_files.py` — подготовка публикуемых файлов.
- `src/git_commit_push.py` — публикация.
- `src/network_filter.py` — фильтр ключей по IP-сетям для WLTest.

Полный тест по всем URL из `whiteList.txt` входит в основной
пайплайн. Отдельно его можно повторить командой:

```bash
python3 src/build_wltest_subscription.py
```

Утилита извлекает все VLESS/Hysteria 2-ключи с буквальным IP из
`normalized_networks.txt` и сразу записывает все совпадения без ping и без
top-лимита в `git/WLTest`. Список кандидатов и JSON-отчет сохраняются в
`file/6NetworkFilteredTest/`.

Параллельность и повторы скачивания задаются в `pipeline_config.py` через
настройки с префиксом `WLTEST_`. Шаг выполняется перед `git commit + push`; при
ошибке загрузки/сборки публикация останавливается и предыдущая подписка не
затирается. Xray на этом шаге не запускается.

## Сохранение ранее опубликованных живых ключей

Перед проверкой через Xray скрипт скачивает опубликованные подписки:

- `main`;
- `WhiteKeys`;
- `WhiteKeys2`.

Их ключи ставятся в начало очереди и повторно проверяются вместе с новыми.
Мертвые ключи удаляются. Живые прежние ключи сохраняются: для `main` и
`WhiteKeys` они добавляются к новому top-300, а `WhiteKeys2` получает остальные
живые RU-ключи.

Во время первого обновления, пока новые имена еще отсутствуют на GitHub,
используются миграционные источники: семь дневных файлов вместо `main` и
`RU_other` вместо `WhiteKeys2`. После успешной сборки дневные файлы и
`RU_other` удаляются. Если GitHub временно недоступен, используется последняя
локальная копия из `git/`.
